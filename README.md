# Yunis Health

A personal health-tracking app: sign up, log in, connect Garmin, see a Datos-Health-style
dashboard of your daily steps/walking/running, and get an email nudge if you haven't hit
your daily step goal (default 8,000) by a time you choose.

## Current status: Garmin mock mode

Garmin's Connect Developer Program (the Health API) is a business-only program that
requires manual approval — an application was emailed to connect-support@developer.garmin.com
and is pending a reply. Until it's approved, "Connect Garmin" on the dashboard uses a
built-in **mock data generator** instead of a real Garmin account, so the whole app —
auth, dashboard, charts, goal badges, notifications — works end-to-end right now.

When real access comes through, wire it up in `backend/src/routes/garmin.ts`
(`/oauth/start` and `/oauth/callback` are stubbed there) and point Garmin's webhook at
`/api/garmin/webhook` (already stubbed to log incoming payloads). The `GarminConnection`
table in the schema already has the fields real OAuth tokens will need.

## Project structure

```
yunis-health/
  backend/     Express + TypeScript + Prisma (PostgreSQL) API
  frontend/    React + Vite + TypeScript + Tailwind dashboard
  render.yaml  Render Blueprint — deploys both services at once
```

## Run it locally

Requires Node.js 18+ and a Postgres database (a free Neon project works great — see
Hosting below; use the same one for local dev, no need to install Postgres yourself).

### 1. Backend

```
cd backend
cp .env.example .env      # then paste your DATABASE_URL (and a real JWT_SECRET / CRON_SECRET)
npm install
npx prisma migrate dev --name init
npm run dev
```

Runs on http://localhost:4000. Commit the generated `prisma/migrations/` folder to git —
hosting uses `prisma migrate deploy`, which only applies migrations that already exist,
it doesn't generate new ones.

### 2. Frontend (separate terminal)

```
cd frontend
npm install
npm run dev
```

Runs on http://localhost:5173.

### 3. Try it

1. Open http://localhost:5173, click "Sign up", create an account.
2. On the dashboard, click **Connect (mock)** — this generates 14 days of simulated
   steps and a few walking/running sessions.
3. Click **Sync now** any time to simulate a fresh sync for today.
4. Go to **Settings** to change your step goal or the time of day you want a reminder.

## Hosting it on the internet (free tier)

Three free accounts, all created by you (I can't create accounts on your behalf):

1. **Neon** (neon.tech) — free Postgres. Create a project, copy its connection string
   into `backend/.env` as `DATABASE_URL`, run `npx prisma migrate dev --name init`
   locally once against it, then commit the resulting `prisma/migrations/` folder.
2. **GitHub** — push this whole `yunis-health` folder to a new repo (`git init`,
   `git add .`, `git commit`, create a repo on github.com, `git remote add origin ...`,
   `git push`).
3. **Render** (render.com) — "New" → "Blueprint", connect your GitHub repo. It reads
   `render.yaml` and creates both the backend web service and the frontend static site.
   Fill in the env vars it asks for (marked `sync: false` in `render.yaml`):
   - Backend: `DATABASE_URL` (your Neon string), `CLIENT_ORIGIN` (the frontend's Render
     URL, once you know it), SMTP vars if you want real emails instead of console logs.
   - Frontend: `VITE_API_URL` = the backend's Render URL + `/api`.
   `JWT_SECRET` and `CRON_SECRET` are auto-generated by Render — copy `CRON_SECRET`'s
   value from the backend service's Environment tab for the next step.
4. **cron-job.org** (or any free scheduler) — create a job that sends a `POST` every
   10–15 minutes to `https://<your-backend>.onrender.com/api/cron/goal-check` with header
   `x-cron-secret: <the CRON_SECRET value from Render>`. This is what makes your daily
   goal reminder fire reliably even though Render's free tier puts the app to sleep when
   idle — the free tier's one real trade-off. It also has a side effect of doubling as a
   keep-alive ping.

## Notifications

A background job checks every 15 minutes whether each user has hit their step goal by
their chosen `notifyTime`. Without SMTP configured, reminders are logged to the backend
console instead of emailed — look for `[notify:console]` lines in the terminal running
`npm run dev` in `backend/`. To send real emails, fill in `SMTP_HOST` / `SMTP_PORT` /
`SMTP_USER` / `SMTP_PASS` / `SMTP_FROM` in `backend/.env`.

## Data model

See `backend/prisma/schema.prisma` — Users, GarminConnection, DailyActivitySummary,
Activity (individual walk/run sessions), HealthMetric (weight/HR/sleep, extensible),
HealthNote (mood/symptom journal), Todo (reminders), NotificationLog.

## A note on this build

The app was originally built and tested against local SQLite, confirmed working end to
end (signup, mock Garmin connect, dashboard chart, settings). It was then switched to
PostgreSQL to support free hosting — that change itself hasn't been run yet, since it
needs a real Postgres connection string (e.g. from Neon) to test against.
